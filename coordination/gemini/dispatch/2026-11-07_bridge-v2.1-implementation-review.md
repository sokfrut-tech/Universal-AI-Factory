## Critical defects already identified in the submitted script
1. `ConvertFrom-Json -AsHashtable` is not supported by Windows PowerShell 5.1.
2. The HTTP POST remains commented out, yet the code sets `WAITING_ACK` and logs successful delivery. This is a false delivery claim.
3. ACK handling is incorrectly placed inside the QUEUED outbound-task loop and does not provide a reliable independent inbound ACK consumer.
4. No actual reverse transport exists; merely routing files to an inbox is not equivalent to Gemini API delivery.
5. A shared `processing` directory and untrusted file names can cause collisions/overwrites.
6. Duplicate task IDs overwrite ledger entries.
7. `Move-Item -Force` does not provide the claimed transactional/atomic guarantees.
8. Ledger corruption is silently converted to an empty ledger, risking loss of task state.
9. Restart recovery is not actually implemented despite the test-plan claim.
10. YAML parsing is incomplete and accepts malformed/partial metadata.
11. There is no backoff timing; retry status can spin every polling interval.
12. The test plan's claims exceed the behavior of the code.

## Implementation constraints
- Do not invent or call an unverified endpoint on localhost:8320.
- Transport must default to disabled and report exactly `TRANSPORT_NOT_CONFIGURED`; never claim API delivery or `WAITING_ACK` when no real transport call happened.
- Prefer a truthful local file-queue mode with explicit limits over pretending this is a complete network message broker.
- PowerShell 5.1 compatibility: do not use `ConvertFrom-Json -AsHashtable`, PowerShell 7-only syntax, or unsupported APIs.
- Validate required frontmatter fields: task_id, from, to, timestamp, type. Restrict agent names and message types to documented values.
- Reject duplicate task IDs without overwriting existing ledger state.
- Use safe generated internal filenames; never trust a user-supplied path/name for filesystem destinations.
- Use atomic file creation/move patterns on the same volume and atomic ledger replacement; preserve a recoverable backup and fail closed if ledger JSON is corrupt.
- Use a single-writer lock so two watcher instances cannot mutate the ledger concurrently.
- Implement restart recovery from ledger + processing files. Any uncertain in-flight transport state must be reconciled, not blindly marked delivered.
- Implement ACK correlation independently from normal outbound processing. Check ack_task_id exists, source/target identities match, and the original task is in a state that permits completion.
- Include bounded retry/backoff only for a real configured transport. When transport is disabled, do not retry or increment attempts.
- Provide a dry-run/self-test mode that does not contact localhost or Gemini API.
- Do not store secrets in the repository or log them.
- Document that this file-bus implementation alone does not create an API connection and cannot be deployed to the user's C:\dr by a GitHub workflow.
