# Security Lab Runbook

## Purpose

Provide a controlled workstation for the Windows/runtime/network/reverse-engineering tools in the factory toolchain. This is a lab profile, not a request to install monitoring software on a personal or production computer.

## Isolation and evidence

1. Use a disposable Windows 11 VM or dedicated test machine, separate from production accounts and customer data.
2. Take a VM snapshot before installing instrumentation.
3. Use synthetic test accounts and test builds. Keep signing keys and production tokens off the VM.
4. Capture only traffic generated by the test app and only on an authorized interface.
5. Store reports with repository, commit, APK/EXE SHA-256, tool version and test timestamp. Redact IPs, cookies, bearer tokens, personal data and payloads before sharing.
6. Delete raw captures after the investigation retention period; preserve only sanitized evidence.

## Windows process and event analysis

- Prefer System Informer for current process trees, handles, modules, threads and network connections. Process Hacker is a legacy predecessor; do not install unofficial repacks or random mirrors.
- Install Sysmon only from Microsoft Sysinternals. Review the event configuration before enabling it. Start with process creation, network connection, image load and registry telemetry appropriate to the investigation; avoid collecting unnecessary command-line secrets.
- Export only the relevant event IDs/time window and sanitize before attaching to a GitHub issue.

Official sources:
- Sysinternals / Sysmon: https://learn.microsoft.com/sysinternals/downloads/sysmon
- System Informer: https://systeminformer.sourceforge.io/

## Network analysis

- Install Wireshark from https://www.wireshark.org/download.html.
- Capture on a dedicated test interface; use capture filters to restrict to the test device/service.
- Start with DNS, destination IP/port, TLS SNI/certificate and connection timing. Decrypt TLS only when the test environment and app owner explicitly authorize it.
- Never upload an unredacted PCAP to a public issue or general-purpose agent.

## APK / native binary analysis

- Calculate SHA-256 before analysis and keep the original artifact read-only.
- Use Ghidra from https://ghidra-sre.org/ for offline static analysis of APK-extracted ELF libraries, PE and other supported formats.
- IDA Free is optional and subject to Hex-Rays terms: https://hex-rays.com/ida-free
- Binary Ninja is optional and requires its own license/trial: https://binary.ninja/
- Record architecture/ABI, file hashes, imports/exports, suspicious permissions/URLs/strings and the analyst's confidence. Do not infer exploitability from a string or disassembly pattern alone.

## Dynamic web/API lab

Use the reusable Factory Authorized DAST workflow only after:
- the target is a test/staging asset controlled by the repository owner or covered by written permission;
- the exact hostname is added to GitHub environment variable SECURITY_ALLOWED_HOSTS;
- the GitHub environment security-lab has required reviewers configured;
- a test window, request-rate limit and rollback contact are known.

ZAP baseline is passive. Wapiti and Nuclei can send active probes. Review their output and stop if the target shows instability. Do not test production or third-party targets by default.
