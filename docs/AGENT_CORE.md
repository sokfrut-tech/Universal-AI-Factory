# Ядро фабрик: агент Hermes

Статус: **подготовка, не запущено**. Этот документ описывает выбор ядра и порядок подключения. Фабрики в этом репозитории пока не работают автоматически.

## Выбор ядра

- **Hermes Agent** (Nous Research), лицензия MIT: https://github.com/NousResearch/hermes-agent
- Подходит для фабрик: работает из терминала и через шлюз (Telegram, Discord, Slack и др.), поддерживает несколько провайдеров моделей, есть планировщик задач (cron) и работа с навыками.
- Альтернатива для сравнения: OpenClaw (MIT): https://github.com/openclaw/openclaw

Выбор ядра не означает, что оно уже проверено на ваших задачах. Перед использованием нужна проверка на тестовом проекте.

## Модели

Конфигурация провайдера задаётся в `config/hermes.example.yaml`. Ключи в репозиторий не записываются: только имена переменных окружения.

| Модель | Как подключить | Что нужно |
|---|---|---|
| Claude (Anthropic) | провайдер `anthropic` | ключ `ANTHROPIC_API_KEY` от вашего аккаунта |
| GPT (OpenAI) | провайдер `openai` или через OpenRouter | ключ `OPENAI_API_KEY` |
| Gemini (Google) | провайдер `gemini` | ключ `GOOGLE_API_KEY` или `GEMINI_API_KEY` |
| Локальная модель | провайдер `custom` (Ollama, LM Studio) | запущенный локальный сервер, без платного ключа |

### О бесплатной работе

- Полностью бесплатного доступа к платным моделям Claude, GPT и Gemini не будет: им нужны ключи вашего аккаунта, и у каждого провайдера есть свои лимиты.
- Бесплатный вариант без ограничений по ключам: локальная модель через Ollama или LM Studio. Качество ниже, но работает на вашем компьютере.
- Не используем обходы ограничений: чужие ключи, общие аккаунты, обход лимитов и условий провайдеров.

## Как фабрики обмениваются задачами

Используется папка `coordination/` (см. `coordination/claude/README.md`):
- `coordination/claude/inbox/` — задания для Claude;
- `coordination/claude/outbox/` — ответы и результаты;
- `coordination/shared/` — общие решения и протоколы.

Агент читает новые файлы в `inbox/`, пишет ответ в `outbox/` и не меняет чужие файлы.

## Правила безопасности

1. Слияние в `main` и публикация (деплой) делаются только после явного подтверждения владельца.
2. Ключи и токены не попадают в репозиторий, в логи и в чат.
3. Агент работает в своих ветках (`feature/...`). Прямой запись в `main` запрещена.
4. Доступ агента к файлам и каналам ограничивается списком. Лишние права не выдаются.
5. Действия, которые видят клиенты (сообщения в боте, публикации на сайте), требуют подтверждения человека.
6. Все изменения записываются в журнал в `docs/` с датой, веткой и результатами проверок.

## Что нужно для запуска

- [ ] Машина для работы агента (компьютер или сервер).
- [ ] Выбранные провайдеры моделей и ключи, введённые владельцем.
- [ ] Список каналов (например, отдельный тестовый бот, а не бот для клиентов).
- [ ] Тестовый проект для первой проверки.
- [ ] Проверка: агент читает задание из `inbox/`, пишет ответ в `outbox/`, ничего не публикует.
